# image-io-responses

## image-io-responses-001

- Vitest: "durable OpenAI Responses image generation > requires cron authentication before provider I/O"
- Mode: run
- Given: The cron secret is configured; one caller sends no credentials and another sends a Clerk session bearer token.
- When: Each caller requests `GET /api/cron/reconcile-image-generations`.
- Then: Both requests return HTTP 401 and OpenAI Responses is never called.

## image-io-responses-002

- Vitest: "durable OpenAI Responses image generation > completes a queued image and notifies its owner without a refresh"
- Mode: run
- Given: A signed-in workspace admin with 10,000 credits uses image model `gpt-image-2.5-flare`, OpenAI accepts the background Responses submission, and the scheduler holds the cron secret.
- When: The member sends `POST /api/image-io/generate`; the scheduler calls `GET /api/cron/reconcile-image-generations`; OpenAI later reports the response complete with usage and the scheduler calls the cron route twice more; the member reads `GET /api/built-in-generations/:generationId`.
- Then: Submission returns HTTP 202 and after the first cron run the generation is `running`. After the later runs it is `completed` with an artifact ID, an `/artifacts/` URL, content type `image/png`, the generated byte size and `privateArtifacts: true`. The same completed body is published on realtime event `built-in-generation:<id>`, and the image bytes are uploaded under `private-artifacts/`.

## image-io-responses-003

- Vitest: "durable OpenAI Responses image generation > lets the owner advance one response without a cron secret and leaves GET observational"
- Mode: run
- Given: A signed-in workspace admin with 10,000 credits uses `gpt-image-2.5-flare` and has a queued OpenAI Responses image generation.
- When: The member reads `GET /api/built-in-generations/:generationId`, then sends `POST /api/built-in-generations/:generationId/reconcile` with no cron secret, then reads the status again.
- Then: The first status read retrieves nothing from OpenAI. The reconcile returns HTTP 200 with the generation `running` and retrieves the provider response exactly once; there is still one submission, and the later status read triggers no further retrieval.

## image-io-responses-004

- Vitest: "durable OpenAI Responses image generation > delivers the provider-backed tool ledger through owner refresh and settles exactly once"
- Mode: run
- Given: A signed-in workspace admin with 10,000 credits uses `gpt-image-2.5-flare`, and OpenAI completes the background response with image and mainline token usage and a revised prompt.
- When: The member sends `POST /api/image-io/generate`, then repeatedly calls `POST /api/built-in-generations/:generationId/reconcile` and `GET /api/built-in-generations/:generationId`.
- Then: Submission returns HTTP 202 with `clientReconciliation: true`, and OpenAI receives a background, stored `gpt-4.1` request with the generation ID metadata, a forced single `image_generation` tool call (model `gpt-image-2.5-flare`, `generate`, 1024x1024, `medium`, `png`) and the prompt. The first reconcile is `running` with no result, no charge and no revised prompt in realtime. The second is `completed` with PNG, size, model, provider `openai`, private artifacts, revised prompt and 9 credits, published on realtime without image bytes. Later reconciles and reads return the identical body; there is one submission and one retrieval, the balance is 9,991, and exactly one PNG is uploaded under `private-artifacts/`.

## image-io-responses-006

- Vitest: "durable OpenAI Responses image generation > keeps a missing-mainline ledger recoverable without charging or storing an image"
- Mode: run
- Given: A signed-in workspace admin with 10,000 credits uses `gpt-image-2.5-flare`, and OpenAI first reports the completed response with no mainline usage (row: `missing-mainline`), later with valid usage.
- When: The member generates an image, calls `POST /api/built-in-generations/:generationId/reconcile` and reads the status; after OpenAI returns valid usage, the member reconciles three more times.
- Then: While usage is missing the generation stays `running` with no result or error, the balance stays 10,000 and nothing is uploaded. Afterwards the first reconcile is still `running` with no result, the next is `completed` with 9 credits, and the last returns the identical body; the balance is 9,991, there is one submission and exactly one PNG upload.
