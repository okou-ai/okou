# feishu-files-history

## feishu-files-history-001

- Vitest: "feishu integration > runs a Feishu DM file with downloadable resource context"
- Mode: run
- Given: A signed-in workspace admin on the Feishu platform has the Feishu integration and debug feature switches, an onboarded workspace with Pro entitlement and a personal subscription model, and a set-up Feishu bot installation that accepts encrypted, signed event callbacks; the Feishu user `ou_feishu_user` has connected their Feishu account through OAuth from the bot DM. The Feishu OAuth token endpoint issues that user token with `expires_in` 0, and the account connection created a managed Feishu custom connector. For the later download, the Feishu API serves `quarterly-report.pdf` as PDF bytes for message `om_file_message` with its raw file key and `type=file`, and confirms the message belongs to the p2p chat `oc_feishu_dm` with the user as a member.
- When: The admin lists `GET /api/custom-connectors`, then Feishu delivers an `im.message.receive_v1` DM file event (message `om_file_message`, a file key over 1,400 characters long, filename `quarterly-report.pdf`) to `POST /api/webhooks/feishu/events/:installationId`, and a Runner heartbeat (`POST /api/runners/heartbeat`) dispatches the Run. The admin reads `GET /api/chat-threads/events` and the new thread's `GET /api/chat-threads/:threadId/event-rows`. The Run's Okou token calls `GET /api/integrations/feishu/download-file` with the opaque file key, a misquoted `message_id=om_misquoted_by_model` and `type=image`. After that Run is cancelled, a new DM text starts a second Run whose Okou token requests the same file key with `message_id=om_file_message` and `type=file`.
- Then: `GET /api/custom-connectors` returns HTTP 200. An active Run's prompt contains `[Feishu file] quarterly-report.pdf`, `[MESSAGE_ID] om_file_message`, `[TYPE] file` and an opaque `[FILE_KEY] feishu_file_<22 characters>` instead of the raw key; the Runner receives the same prompt, and its system prompt mentions `okou feishu download-file -h` and `okou feishu upload-file -h`. The OAuth token endpoint saw only the `authorization_code` grant and no refresh. The execution has an inline firewall `custom_connector_<connector id>` for `https://open.feishu.cn/open-apis/` with a secret-backed Authorization header and the permission groups standard:use, messages:send-as-user, resources:delete, sharing:manage, chats:manage, comments:write, calendar:write and tasks:write; its network policy allows standard:use, sharing:manage, comments:write, calendar:write and tasks:write, denies messages:send-as-user, resources:delete and chats:manage, asks for nothing and denies unknown requests; the connector's skill mount carries the SHA-256 of the only managed Skill bundle published during the test. The thread reads return HTTP 200 and the thread holds a user message with null content and exactly a `quarterly-report.pdf` file part, a text part containing the file prompt, and a `feishu` source part linking to `https://applink.feishu.cn/client/chat/open?openChatId=oc_feishu_dm`. The first download returns HTTP 200 with `x-file-name: quarterly-report.pdf` and the exact PDF bytes, fetched from Feishu with the original message ID, the raw key and `type=file`; the second Run's download returns HTTP 400.

## feishu-files-history-002

- Vitest: "feishu integration > runs a rich post with imported and native images in p2p"
- Mode: run
- Given: Row `p2p`. A signed-in workspace admin on the Feishu platform has the Feishu integration and debug feature switches, an onboarded workspace with Pro entitlement and a personal subscription model, and a set-up Feishu bot installation that accepts encrypted, signed event callbacks; the Feishu user `ou_feishu_user` has connected their Feishu account through OAuth from the bot DM. The Feishu API returns PNG bytes for the post image `img_post_first` and HTTP 503 for other message resources; at the download step it serves `img_post_second` for the post message and confirms the message belongs to the p2p chat `oc_feishu_dm` with the user as a member.
- When: Feishu delivers the same `im.message.receive_v1` post event twice to `POST /api/webhooks/feishu/events/:installationId` in the DM chat `oc_feishu_dm`. The post is titled `Image comparison` and contains `Compare these images with` plus a link `the brief`, then the images `img_post_first` (720x1080), `img_post_second` and `img_post_first` again. A Runner heartbeat dispatches the Run, the Run's Okou token downloads the remaining image reference through `GET /api/integrations/feishu/download-file`, the admin reads the thread events, and the Run reports the assistant text `Here is the image comparison.` via `POST /api/webhooks/run/events` and completes via `POST /api/webhooks/run/complete`.
- Then: The first delivery returns HTTP 200 and exactly one active Run exists. The Runner prompt contains `Image comparison`, `Compare these images with [the brief](https://example.com/brief)`, one imported `[ID]` file and exactly one opaque `[FILE_KEY]` reference without the raw key. Exactly one upload is stored: the PNG bytes as `image/png` in the private artifacts bucket; `GET /api/web/file-url` for the imported file returns HTTP 200 for the admin (a URL, no public URL) and for the Run's Okou token, and the thread lists it as an `image/png` file part. Downloading the `[FILE_KEY]` returns HTTP 200 with the Feishu bytes, requested from Feishu with `type=image`. The thread's user message has exactly two file parts named `image` (the first is the imported file), a text part containing `Image comparison` and the linked line, and a `feishu` source part. After completion the bot replies to the original post message in thread (`reply_in_thread` true) with the assistant text.

The Feishu chat history for the DM holds four messages: a `Review request` post from Linghan (`ou_feishu_user`) mentioning Reviewer (`ou_reviewer`) with the text `check this screenshot` and image `img_history_post`; a legacy bot card (Okou) with `The earlier report is ready.` and a `Download report` button to a report URL; a schema 2.0 bot card with `I fixed the chart and created the [deck](<deck URL>).`, a `Download source` open-URL button and image `img_history_card` with alt `Chart preview`; and a bot file message `source.pptx` (`file_history_deck`). Feishu returns the original card JSON only when asked for `card_msg_content_type=user_card_content` and otherwise a rendered preview image; for downloads it serves each resource and confirms the message belongs to the p2p chat `oc_feishu_dm` with the user as a member.
- When: Feishu delivers the DM text `Revise the deck using the previous answer and screenshot` to `POST /api/webhooks/feishu/events/:installationId`, a Runner heartbeat dispatches the Run, the Run's Okou token downloads each history resource through `GET /api/integrations/feishu/download-file`, and the admin cancels the Run with `POST /api/runs/:id/cancel`.
- Then: The Run's conversation history (system prompt) lists the senders `{id: ou_feishu_bot, name: Okou}` and `{id: ou_feishu_user, name: Linghan}` and renders `@Reviewer (ou_reviewer) check this screenshot`, `The earlier report is ready.`, the deck markdown link, `[Download source](<source URL>)`, `[Download report](<report URL>)`, `Chart preview` and `[Feishu file] source.pptx`, with relative indexes -4 and -1. It contains exactly three opaque `[FILE_KEY]` references and no raw keys; each downloads with HTTP 200 and the Feishu bytes (`img_history_post` and `img_history_card` with `type=image`, `file_history_deck` with `type=file`). The cancel returns HTTP 200.

The three generic connector-account requests return HTTP 404. The thread's connector selections return HTTP 200 with empty `selections` and `selectedConnections`. The PUT returns HTTP 200 echoing the connection ID and custom target, and a `chatThreadDetailChanged:<threadId>` realtime message is published with a null payload.
