# Dependency override audit

Initial audit: 2026-09-12 against main c3e7211fec24c53fae7b5d4e9d13e8dc5bc8be56. Follow-up: 2026-09-13 against main 26ce7160cda683af46ec47fb588e0dfd7f425496 ([#33726](https://github.com/vm0-ai/vm0/pull/33726)).

This audit covers the 79 entries in `turbo/pnpm-workspace.yaml` under `overrides`. It does not delete package-manager lockfiles. `pnpm-lock.yaml` and `Cargo.lock` remain the reproducible dependency graphs; the three Pi patches and their exact version associations remain because they modify runtime behavior.

The initial cleanup retained 11 overrides, removing 68. This follow-up removes four more through compatible upstream dependencies, leaving seven overrides (72 fewer than the original 79). Tiptap's 19 direct declarations now match its already installed 3.31.0 version, making 28 blanket editor overrides unnecessary (including seven packages no longer in the graph).

The additional `@testing-library/jest-dom@6.9.1` patch changes only its Vitest declaration from the obsolete single-parameter `Assertion` augmentation to Vitest 5's public `Matchers` interface. UI's Node type resolution is aligned with Platform and the root test tools so both consumers share Vitest's matcher declarations. Remove this test-only patch when an upstream jest-dom release supports Vitest 5; the three Pi runtime patches remain unchanged.

## Initial audit method and limits

- Read all 25 commits touching the workspace configuration and the relevant source PRs. Many entries first appeared together in #22454 as dependency hardening; that PR did not document a separate rationale for each entry. Historical purpose below is classified from those changes, not a claim that every original pin had a dedicated advisory.
- Resolve an isolated copy with all overrides removed using the repository's pnpm 10.33.4 and unchanged seven-day release-age policy; compare package versions and peer warnings against the consolidated dependency graph before cleanup.
- Resolve the retained subset and aligned direct Tiptap declarations, then run the full dependency audit again. The fully unpinned experiment exposes 60 advisories, including one critical; the pre-cleanup consolidated graph has 25, and the retained subset has 20. There are no new advisory URLs in the final graph compared with the pre-cleanup graph. These counts are a registry snapshot, not a claim that the repository is vulnerability-free.
- Existing remaining advisories involve sharp, extract-zip, nanoid, @xmldom/xmldom, adm-zip and smol-toml. This cleanup does not add blanket overrides for unrelated dependencies or new audit exclusions.
- An unchanged lockfile selection alone does not prove a pin is unnecessary: inspect upstream constraints too. In particular, jayson 4.3.0 still requests stream-json ^1.9.1, so its 4.1.3 compatibility pin stays.

### Follow-up validation

The live baseline audit has 20 advisories (3 moderate, 17 high). The final graph has 19 (3 moderate, 16 high), with no new advisory URLs; GHSA-f88m-g3jw-g9cj is removed. Wrangler 4.129.0's Miniflare still requires sharp 0.35.2, so the existing GHSA-rgj7-g3m4-5g8c remains. Counts describe this registry snapshot, not a vulnerability-free graph or the result of a different Wrangler release. The existing Axiom logging peer warning (`@axiomhq/logging` 0.1.7 expects `@axiomhq/js` 1.3.1; the project uses 1.5.0) is unchanged.

All 70 newly resolved package versions were checked against npm publication timestamps and are at least 10080 minutes old. Sentry's compatible `import-in-the-middle ^3.0.0` range resolves to 3.4.0, as selected by a fresh isolated resolver with the seven-day policy; this avoids the newer 3.5.1 / es-module-lexer 3.0.2 releases. Their generated package and snapshot entries were carried into the workspace lockfile and normalized by pnpm. The final frozen installation with `--config.minimumReleaseAge=10080` succeeds, including an offline installation into a clean workspace copy. In that clean copy, Desktop's Electron, Node, node-core and OpenTelemetry Sentry packages all resolve core 2.11.0. Re-resolving the entire existing workspace with that flag is blocked by the baseline UI `@types/node ^24.13.4` release, published on September 10; this follow-up preserves that existing declaration and lock selection and adds no release-age exclusions.

Executable compatibility checks:

- 200 focused Vitest cases pass across API (149), CLI (5), Desktop (1) and host-worker (45), plus the app-worker Node test harness. API coverage includes tracing/database spans, app errors, automation result emails, mail drafts and Teams dispatch.
- New regressions invoke the production telemetry initialization with the real Sentry and OpenTelemetry SDKs, intercept their HTTP transports with MSW, explicitly flush and close the SDKs, and verify Axiom trace metadata, Sentry error delivery and CLI operational-error/log exclusion. The shared MSW setup synchronizes Node's named ESM HTTP exports when installing and restoring interceptors.
- Affected-workspace type checks and lint pass. API and CLI production builds, Desktop's main/preload/bootstrap and renderer builds, and its bootstrap bundle guard pass.
- Wrangler 4.129.0 dry runs pass for app-worker preview `versions upload` and production `deploy` (including preview alias and fixture secret files), and host-worker test/production `deploy`. App-worker uses a shell fixture prepared by the repository script from tracked Platform assets; this checks bundling/configuration, not a production Platform deployment. Native macOS packaging and live Cloudflare deployment were not run. The full test suite remains a PR-pipeline check.

### Compatibility review

- [Sentry 10.57.0](https://github.com/getsentry/sentry-javascript/releases/tag/10.57.0) preserves legacy `sendDefaultPii: false` behavior when `dataCollection` is absent; keep that configuration. [10.71.0](https://github.com/getsentry/sentry-javascript/releases/tag/10.71.0) changes `enableLogs` to default to true. Explicitly disable logs in API, CLI and both Desktop initialization paths to retain the existing error-reporting policy. [Electron 7.18.0](https://github.com/getsentry/sentry-electron/releases/tag/7.18.0) also makes integration log emission opt-in; this app did not enable Sentry Logs.
- Desktop passes React's `init` to Electron's renderer initializer. Type checking exposed incompatible 10.50.0/10.73.0 client and integration types, so Desktop's `@sentry/react` also moves to ^10.73.0 and resolves to 10.73.0. Platform's separate React SDK declaration is unchanged.
- API keeps `@vercel/otel` as the tracing owner, its Axiom OTLP endpoint and headers, and Sentry's `skipOpenTelemetrySetup`, zero trace sampling and disabled HTTP/fetch trace propagation. The [OpenTelemetry 2.9.0](https://github.com/open-telemetry/opentelemetry-js/releases/tag/v2.9.0) new `sdk-trace` constructor signatures do not apply to the retained `sdk-trace-base` imports. The [0.222.0](https://github.com/open-telemetry/opentelemetry-js/releases/tag/experimental/v0.222.0) declarative `sdk-node` startup changes do not apply to this initialization path.
- [Wrangler's upgrade notes](https://github.com/cloudflare/workers-sdk/blob/wrangler%404.129.0/packages/wrangler/CHANGELOG.md) preserve the configured `deploy`, `versions upload`, `--preview-alias` and `--secrets-file` interfaces. Its Node >=22 requirement is within this workspace's Node >=22.19.0 requirement. Both Worker compatibility dates, routes and bindings remain unchanged. Local upload dry runs validate bundling/configuration; actual Cloudflare deployment is left to the PR and release pipelines.
