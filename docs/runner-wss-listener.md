# Runner WSS listener and admission (#37027)

This is a **draft, non-activating** Runner slice under #36981. Do not merge/deploy it before the prerequisites below. Startup shares the executor's exact `RunGuestChannels` registry with WSS admission. A missing, mismatched or cancelled assignment is rejected before ticket consumption; successful attachment requires the provider's initialized Guest `ACTIVATED` acknowledgement before `auth.ok`. Tests exercise the real registry and framing through a provider-boundary echo fixture, not a real Firecracker Guest image or browser/Caddy path. Established-stream owner revocation and integrated acceptance remain unresolved; wiring the private channel is not production activation.

## Health and host contract

Official Runners (not `runner local` test/development jobs) require a pre-existing trusted `/run/okou-ws` directory. The Runner holds its exclusive base-dir/identity lock, validates the directory and obtains the per-ID kernel-held socket-owner lock. It recovers only a proven owned, dead previous endpoint, then binds and safely publishes `<runner_id>.sock` and starts its supervised accept/admission task before provider readiness, healthy status, heartbeat or claiming. Accepted sockets enter bounded admission immediately, even while startup or the main reactor is waiting; no raw-socket queue can postpone the five-second pre-auth deadline. Normal teardown cancels and joins the admission tasks before removing the owned listener socket. Missing/unsafe/symlinked directories or permissions, a held owner lock, an unrecorded/replaced endpoint or uncertain/live listener fail startup. An accept task failure stops healthy claims/heartbeats and follows normal Runner teardown. Sockets are removed only if their file identity remains the one created by the process. Soft-draining Runners retain their own listener while they still have runs; release-specific Runner IDs do not share a socket. This is not a separate host lease or health prober.

#38073 / merged PR #38100 owns ordinary provisioning and boot restoration of the directory and group **independently of Caddy**. These filesystem prerequisites must exist before deploying the mandatory listener. The host contract is `/run/okou-ws` owned `root:okou-wss-caddy` at exact mode `0710` (not setgid). The Runner verifies that owner/group, pins the bound pathname socket inode without following symlinks, then assigns the parent group and exact mode `0660`. On Linux the listener FD refers to a different inode and must not be used to set pathname ownership. Permission changes use the pinned filesystem inode; its type, identity, owner, group and mode are verified before startup succeeds. The host must restrict group membership. Neither the Runner nor this PR creates DNS/TLS, Caddy routing or public firewall exposure.

#37028 owns optional Caddy/TLS/public ingress. Missing, stopped or unqueryable Caddy must not block ordinary Runner startup, claims, heartbeats or this private listener; it only denies new WSS ticket issuance. There is no API issuance switch: #37025 already permits explicit, owner-authenticated on-demand bootstrap with a 30-second one-use ticket. A candidate target is not proof of ingress readiness. No production Web adapter or ingress activation is authorized here.

### Crash-only socket recovery

The private directory also holds a root-owned `0600` `<runner_id>.lock` and `<runner_id>.owner`. Never remove the lock pathname: every generation must lock the same inode, including copied identities in different base directories. Before publishing a new endpoint, the owner atomically writes and syncs bounded inode evidence, including a random `.wss-<uuid>` anchor name. Linux publication hard-links the pinned socket inode without replacing a target. Retain that private anchor for the listener lifetime and after an abnormal exit; it prevents inode reuse from authorizing deletion of a replacement socket.

Recovery requires the exclusive nonblocking lock, intact private regular ownership files, matching socket inode/device/timestamps/owner/group/mode, the retained anchor whenever the public pathname exists, and a nonblocking connect returning exactly `ECONNREFUSED`. All candidates are checked before cleanup. Unknown, legacy-unrecorded, replaced, symlinked, live or uncertain endpoints are not removed. Cleanup is relative to the pinned directory and checks inode identity; it does not follow a replaced parent symlink. Persistent lock/journal files are intentionally retained after normal stop. A kill before recording/publication can leave an unrecorded hidden temporary node, never an unrecorded Runner-ID endpoint; unknown files require operator handling, not blind pruning.

Native regressions SIGKILL an isolated process using the actual socket-owner implementation, then rebind the same Runner ID and verify traffic and cleanup. Both the published and recorded-before-publication windows are covered, as are a still-live owner, absent anchor, unknown dead endpoint, special ownership files and replacement symlinks. These are native filesystem/listener regressions, not a full official Runner/Firecracker restart E2E.

The Linux different-GID regression requires root or a supplementary group different from the test process's effective GID. It uses only an isolated temporary directory, verifies pathname ownership/mode and real socket traffic, and does not modify host groups or process credentials.

## Wire and ownership

Caddy should forward only `/ws/<runner_id>` to the matching socket. The listener refuses other paths, query strings, ordinary HTTP and malformed WebSocket handshakes. It allows at most 32 connected tasks and 16 simultaneous pre-auth handshakes, with a five-second total pre-auth deadline. The first application frame is JSON `{"runId":"<uuid>","ticket":"<43-character-base64url>"}` (maximum 256 bytes). The token is never part of the URL or logs. Using its configured and validated hostname, the Runner requests #37025's official-Runner ticket consumption with the exact run, runner ID and `wss://<hostname>:443` origin; a non-success, outage or mismatched response is denied.

The destination process then checks its **current** `ActiveRuns` guard and in-memory `StatusTracker` Running-phase `(runId,sandboxId)`, not a status file, DB row, hostname/path, heartbeat generation or parked-sandbox cache. The same executor-owned registry provides a non-authorizing exact-assignment preflight before consumption. After consume, `RunGuestChannels::open_for_sandbox(run_id, sandbox_id)` atomically resolves and holds the matching live execution epoch and waits for Guest activation; the status mapping alone grants no Guest access. Local proofs are rechecked before `{"type":"auth.ok"}`. Subsequent messages are opaque binary frames up to 64 KiB, with the native eight-stream/run limit, no bridge tasks or staging queues and at most one pending frame per direction. Native Unix/vsock IO supplies backpressure. Retain `Channel::cancellation()` before splitting and independently select it during authentication, idle IO and blocked forwarding. Keep a partial native receive inside a pinned stream across status ticks and client sends; dropping and recreating it could lose header/payload bytes. The same 250 ms live status check continues during blocked forwarding to cover early removal/reassignment, preserving the pending send and original 15-second stalled-write deadline. On liveness/deadline/Guest error, drop the transport and native halves without flushing canceled application bytes. A normal peer close receives a bounded graceful acknowledgement. Any non-binary application message after authentication closes the stream.
