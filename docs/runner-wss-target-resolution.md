# WSS target resolution (API-only prerequisite)

The API resolver in `turbo/apps/api/src/signals/services/runner-wss-target.service.ts` is an **internal, read-only prerequisite** for #37025. It never issues a ticket or returns a browser URL. Its result explicitly marks `ingressVerification: "not-observed"`; neither its result nor a Runner heartbeat proves that DNS, TLS, Caddy or the Unix listener is currently reachable. #37027 must reject a ticket for a run absent from that process's live run-to-sandbox registry, including after a same-ID restart.

The service requires the owner's organization and user ID, an `agent_runs` row with `status=running`, its `active_agent_runs` row, winning official Runner attribution, a matching `runner_state` group and a heartbeat in the last 30 seconds. Both `running` and `draining` Runner modes can serve **already owned** runs; `starting` and `stopping` cannot. A heartbeat can temporarily outlive a dead Runner, so a selected target is not authorization. No WSS-specific heartbeat-generation comparison is made. Old/PAT/non-official/null claims are ineligible.

The official Runner's Ansible-configured `inventory_hostname` is the intended browser-facing WSS DNS name. The resolver validates the claimed snapshot as a canonical lowercase, multi-label DNS hostname (not an IP literal, local-only name, path, port or URL) and constructs `wss://<runner_hostname>:443` without a second hostname-to-origin mapping. The hostname is **not** a credential or a reachability proof; only an authenticated official Runner can claim the run, and the eventual destination Runner must independently authorize the currently live run. When replacing a host, keep its old DNS/IP/certificate pointed to that host until its runs drain; never silently repoint a still-serving name.

The sole optional API setting is `OKOU_WSS_MIN_RUNNER_VERSION`, an exact numeric `MAJOR.MINOR.PATCH` for the **first future release** in which every official Runner must bind/supervise the WSS listener before healthy startup/claims (#37027). The resolver is **disabled by default** until this version is configured. Do not set it to a deployed pre-WSS release or infer support from an arbitrary claim header. Numeric comparison admits that version and later versions in the same major series, not malformed/prerelease or a different major (review compatibility on major upgrades). An invalid setting fails API environment validation at startup; removing it disables all target lookups.

#37028 must separately verify DNS-only address, browser-trusted TLS and Caddy routing **for every eligible hostname** before #37025 enables ticket issuance. There is no per-host mapping/allowlist to activate some hosts implicitly; if any eligible host is not ready, keep ticket issuance off or establish a separately reviewed eligibility gate in #37025. #37030 validates the real non-production browser→Caddy→Runner→Guest path before any production activation. This resolver has no public route, DB migration, host identity credential, sidecar registrar or readiness lease. Because #37025 has not yet exposed authenticated bootstrap, its DB-backed integration tests use the existing gated `/api/test/runtime-state/action` support route to read this internal resolver after creating real Runs/claims/heartbeats through the API; production clients cannot call that test route. Database failures propagate rather than being converted into an absent target.
