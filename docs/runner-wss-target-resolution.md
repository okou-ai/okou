# WSS target resolution (API-only prerequisite)

The API resolver in `turbo/apps/api/src/signals/services/runner-wss-target.service.ts` is an **internal, read-only prerequisite** for ticket issuance. It never issues a ticket or returns a browser URL. For **new ticket issuance**, it requires a fresh, official-Runner-reported `wssIngressServiceActive` observation that the host's dedicated WSS ingress service was active (currently `okou-wss-caddy.service`); missing, inactive, untrusted or stale observations reject issuance. Its result still marks `ingressVerification: "not-observed"`: local service state does **not** prove DNS, browser-trusted TLS, port 443, route correctness or the Unix listener is currently reachable. #37027 must reject a ticket for a run absent from that process's live run-to-sandbox registry, including after a same-ID restart.

The service requires the owner's organization and user ID, an `agent_runs` row with `status=running`, its `active_agent_runs` row, winning official Runner attribution, a matching `runner_state` group and a heartbeat in the last 30 seconds. New issuance additionally requires `wss_ingress_service_active = true` on that same fresh heartbeat. The sole heartbeat writer updates this status and `last_seen_at` together under generation/sequence ordering; PAT or missing-field heartbeats clear the status, so a separate observation timestamp is unnecessary. Both `running` and `draining` Runner modes can serve **already owned** runs; `starting` and `stopping` cannot. A heartbeat can temporarily outlive a dead Runner, so a selected target is not authorization. No WSS-specific heartbeat-generation comparison is made. Claims without winning official Runner identity or a usable hostname remain ineligible; a claimed release number is diagnostic, not a capability check.

The official Runner's Ansible-configured `inventory_hostname` is the intended browser-facing WSS DNS name. The resolver rejects malformed hostnames, IP literals (including abbreviated/hex/octal forms normalized by browser URL parsers) and known local/reserved suffixes, then constructs `wss://<runner_hostname>:443` from a canonical lowercase, multi-label DNS name without a second hostname-to-origin mapping. A syntactically accepted name may still be privately resolved, misconfigured or unreachable; this check does not establish public DNS ownership or reachability. The hostname is **not** a credential or a reachability proof; only an authenticated official Runner can claim the run, and the eventual destination Runner must independently authorize the currently live run. When replacing a host, keep its old DNS/IP/certificate pointed to that host until its runs drain; never silently repoint a still-serving name.

There is no API-side Runner version floor in this resolver. A Runner without a trusted positive WSS ingress service observation is ineligible for new ticket issuance, including an older heartbeat without the field. Consumers must never treat a resolved target as evidence that the listener exists. #37027 makes WSS listener bind/supervision mandatory before a new Runner is healthy or claims work. The host-local ingress service filter is not listener evidence and applies only to new ticket issuance, not redemption of a previously issued ticket. Normal run attribution, expiry and one-use redemption checks still apply; the filter neither recalls existing tickets nor closes established streams. The bootstrap endpoint has no issuance switch: it issues only for an eligible owner-initiated request, and older Runners without the new observation remain ineligible. Before activating production ingress or connecting Web business traffic, verify listener readiness for every selectable serving Runner (including draining owners), drain pre-WSS Runs, and preserve the rollback boundary; this filter does not replace those gates.

#37028 must separately verify DNS-only address, browser-trusted TLS and Caddy routing **for every hostname that ticket issuance could select** before production ingress activation. There is no per-host mapping/allowlist that activates some hosts implicitly; do not infer public reachability from the heartbeat observation. #37030 validates the real non-production browser→Caddy→Runner→Guest path before any production activation. This resolver has no public route, separate host identity credential, sidecar registrar or readiness lease; #37189 adds one boolean to the existing `runner_state` table, not a readiness table. The DB-backed target tests use the gated `/api/test/runtime-state/action` support route after creating real Runs/claims/heartbeats through the API; production clients cannot call that test route. The separate owner-authenticated bootstrap is the only ticket-issuing route. Database failures propagate rather than being converted into an absent target.
