# WSS target resolution (API-only prerequisite)

The API resolver in `turbo/apps/api/src/signals/services/runner-wss-target.service.ts` is an **internal, read-only prerequisite** for #37025. It never issues a ticket or returns a browser URL. Its result explicitly marks `ingressVerification: "not-observed"`; neither its result nor a Runner heartbeat proves that DNS, TLS, Caddy or the Unix listener is currently reachable. #37027 must reject a ticket for a run absent from that process's live run-to-sandbox registry, including after a same-ID restart.

The service requires the owner's organization and user ID, an `agent_runs` row with `status=running`, its `active_agent_runs` row, winning official Runner attribution, a matching `runner_state` group and a heartbeat in the last 30 seconds. Both `running` and `draining` Runner modes can serve **already owned** runs; `starting` and `stopping` cannot. A heartbeat can temporarily outlive a dead Runner, so a selected target is not authorization. No WSS-specific heartbeat-generation comparison is made. Old/PAT/non-official/null claims are ineligible.

The default configuration is **disabled**. Two optional API settings must be explicitly supplied together:

- `OKOU_WSS_HOST_ORIGINS`: a JSON array of unique entries with exact `inventoryHostname` and `publicOrigin` strings. For example, `[{"inventoryHostname":"runner-a.example.com","publicOrigin":"wss://runner-a-wss.example.com:443"}]`. The inventory key is the Runner's claimed hostname, **not** a URL. Origins must be canonical lowercase DNS WSS authorities with an explicit `:443`, no credentials, path, query, fragment, IP literal or local-only name. Invalid JSON, duplicate/unsafe mappings and malformed minimum versions fail API environment validation at startup; a missing or unmatched entry yields no target. The mapping is never interpolated directly from the run claim. Keep the old host entry pinned while its runs drain during replacement; do not repoint it to another machine.
- `OKOU_WSS_MIN_RUNNER_VERSION`: exact numeric `MAJOR.MINOR.PATCH` for the **first future release** in which every official Runner must bind/supervise the WSS listener before healthy startup/claims (#37027). This value is deliberately **unset** until that release is built and verified; do not set it to a currently deployed pre-WSS release or infer support from an arbitrary claim header. Numeric comparison admits that version and later versions in the same major series, not malformed/prerelease or a different major (review compatibility on major upgrades).

The hostname map must be provisioned by operators only **after** #37028 independently verifies each host's DNS-only address, browser-trusted TLS and Caddy route. #37025 separately controls bootstrap and ticket activation; #37030 validates the real non-production browser→Caddy→Runner→Guest path before any production activation. This resolver deliberately has no public route, DB migration, host identity credential, sidecar registrar or readiness lease. Because #37025 has not yet exposed authenticated bootstrap, its DB-backed integration tests use the existing gated `/api/test/runtime-state/action` support route to read this internal resolver after creating real Runs/claims/heartbeats through the API; production clients cannot call that test route. Rollback is removing either setting, which makes every lookup unavailable without changing stored run attribution or existing transports. Failures of the database are errors, not silently converted into an absent target.
