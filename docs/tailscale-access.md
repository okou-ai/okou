# Tailscale private SSH access

Delivery parent: [#36137](https://github.com/okou-ai/okou/issues/36137). The API/data foundation is [#37638](https://github.com/okou-ai/okou/issues/37638); the qualified official native Rust carrier and setup/recovery UI are separate siblings [#37639](https://github.com/okou-ai/okou/issues/37639) and [#37640](https://github.com/okou-ai/okou/issues/37640). This foundation does not make private SSH operational. The current Runner explicitly rejects the new JIT variant before DNS, OS TCP or SSH; it never treats it as Direct/Cloudflare. Saving never performs a provider request or tailnet join.

## Common configuration behavior

Except for registration credentials, tags, private-peer destinations and the qualified native carrier, behavior follows [Cloudflare Access](cloudflare-access.md).

Canonical routes are `/api/tailscale/configs` (list/create), `/api/tailscale/configs/:configId` (update/delete), and `/:configId/convert-to-organization`, `/:configId/impact-preview`, `/:configId/convert-to-personal`. There is no separate detail route. Personal metadata is visible/manageable only to its owner in the selected organization. Members may select Organization configurations; only current Organization admins may create/manage shared configurations. Metadata contains scope, name, tags, revision/generation, timestamps and only the caller's host IDs/names, never credentials/ciphertext.

Standalone creation requires an explicit UUID and name plus OAuth client ID/secret (write-only, individually bounded to 4096 ASCII non-whitespace characters) and 1–16 unique registration tags. Same UUID/owner retries reconcile with 204 without overwriting stored values; foreign UUIDs conflict. Updates require `expectedRevision`. Names advance revision only; credential replacement and effective tag changes also advance configuration generation and **all current referencing host generations atomically**, preserving trust and login. Tags are compared by set membership: reordering the same tags advances metadata revision only, preserves configuration/host generations and sends no runtime invalidation; adding or removing a tag remains effective. Edit, pin and observation freshness use the shared SSH host generation, not a second Tailscale guard or observation tuple. Post-commit notices use the protected binding set, grouping owners in batches of 16. Realtime is best effort, not authority.

A current admin can promote their own Personal configuration to Organization, preserving its ID, credentials and eligible bindings. Organization-to-admin-Personal conversion requires a fresh aggregate impact preview and exact revision/snapshot confirmation. Other owners' hosts retain endpoints, logins and pins but become explicit `transport: { type: "tailscale", needsRebind: true }`. Their configuration reference is cleared; their hosts are never inferred Direct. The new Personal owner retains eligible bindings, and the former creator has no special ownership privilege.

Deletion refuses the actor's own referencing hosts. A current admin can delete an Organization configuration referenced only by others after reviewing/confirming the current impact snapshot. Other hosts enter the same retained rebind state. A changed reference set or host generation invalidates the snapshot; previews expose only counts/affected-owner display metadata, never another owner's host IDs, names, destinations or credentials. Configuration deletion does not forcibly revoke previously admitted Run caches, matching Cloudflare. User deletion erases Personal encrypted configuration after dependent hosts; creator-only deletion preserves shared configuration. Organization deletion removes all its Personal/shared configurations after dependent hosts.

## Saved SSH hosts and transactions

The saved-host foreign key is `tailscaleId` (`tailscale_id` in PostgreSQL), following `cloudflareAccessId` without an extra configuration suffix. The public transport and nested JIT network objects retain their common `configId` field, matching Cloudflare.

`transport: { type: "tailscale", configId }` selects visible configuration. `transport: { type: "tailscale", create: { name, credentials, tags } }` atomically creates a Personal network with a server-generated UUID, independently of a new/reused SSH login. As for Cloudflare, the explicit host UUID is the reconciliation identity; retrying that host does not create another network/login, while a new host may create a distinct inline network. A failed binding or stale editor leaves no inline resources. Configuration metadata notifications on host writes occur for inline creation; ordinary binding edits/deletion use the common SSH notification.

Encryption/preparation occurs outside DB transactions. Host updates reject already-missing or invisible selected configurations before encrypting a new SSH login, matching Cloudflare; the unlocked visibility preflight does not replace the transaction's authoritative binding admission.

**Metadata-only path:** name-only updates and tag permutations without credential replacement use one command-owned SQL statement, without an explicit transaction. A locking configuration CTE retains the existing `FOR UPDATE` fence and captures current-scope permission, expected revision, tag membership and exhaustion for both success and rejection. A dependent conditional update accepts only the same tag set and cardinality and advances revision with atomic arithmetic; returned configuration fields come from its `RETURNING`, not a stale base-table reread. Only name/tag order, revision and timestamp change. Configuration/host effective generations, login, endpoint, binding and trust remain unchanged. Caller-owned host IDs/names are nonlocking observations from the statement's initial MVCC snapshot, not a post-wait impact or authority snapshot; the metadata timestamp is captured when constructing the statement. No host lock/write follows the configuration fence, and only configuration metadata invalidation is published after commit. Preflight classification is not authority and cannot admit a tag membership change through this path.

**Unresolved merge gate:** the effective multi-row protocols and new binding/cleanup paths described below still execute non-billing transactions. They are not exceptions to the stricter [API ccstate transaction policy](./api-ccstate.md#10-keep-database-handles-local-and-prefer-atomic-sql). The foundation remains blocked until a reviewed transaction-free design preserves their authority, exact impact and atomicity. Moving SQL into an owning command or passing tests does not satisfy this gate.

Credential replacement, tag additions/removals, deletion and scope conversion retain UUID-ordered referencing-host `FOR NO KEY UPDATE` before configuration `FOR UPDATE`. Under PostgreSQL READ COMMITTED, the locking reader rechecks a tuple changed while it waited: deleted/rebound nonmatches are omitted, and an updated matching tuple is returned and retained under its lock. The **actually returned** locked records cannot subsequently disappear, rebind or change their impact metadata before commit. Their set is therefore a subset of the fresh post-fence references selected with the identical organization/configuration predicate. The second query selects decoded `count()` only: equal cardinality proves equal identity under that retained-set premise, and the ordered locked records are reused for exact impact, generations, response and notifications. It is not a general claim that counts equal sets. A smaller count or missing aggregate row is a broken invariant and throws; a larger count permits only one fresh **known-unwritten** transaction, without repeating encryption. A second expansion conflicts. Transaction-held configuration `FOR SHARE` on selected binding admission prevents later additions after the exclusive fence. Successful/ambiguous effects, provider actions and exceptions are never blindly replayed.

This removes broad metadata-update host locking and a duplicate full host projection/application ID set. Reference counting still scans the matching set and effective changes still synchronously perform O(N) host writes; no latency/throughput improvement has been measured. The local optimization neither changes schema/DTOs nor establishes serving/rollback writer readiness. The current rebase retains main's independently repaired Cloudflare writer protocol with only the canonical carrier/shadow adaptations; this is not a global or bulk-cleanup concurrency certification.

SSH login rotation retains the same host-before-credential fence and bounded unwritten rescan. `FOR NO KEY UPDATE` remains compatible with restrictive deletion's key-share check. Credential deletion takes its exclusive fence and uses a nonlocking reference precheck; it never takes host locks in reverse order. Restrictive owner/org FKs remain final integrity guards. No KMS/provider IO, advisory locks or generic retry runs under these locks.

Ports are 1–65535 rather than Cloudflare's WSS443 rule. Syntax-only targets accept Tailscale assigned IPv4/IPv6 literals, selected-tailnet short names and exact FQDNs. URLs, wildcards, zones, Unicode labels, alternate IP spellings and arbitrary private/public literals are rejected. The native sibling must prove the exact eligible peer through the selected tailnet, exclude self/foreign/shared peers and advertised routes, and never use public/system DNS or fallback carriers. Saved-name validation is not general MagicDNS/split DNS or membership proof.

Omitted transport preserves a binding; retained rebind requires an explicit visible protected configuration or an explicit Direct choice. Protected endpoint/port edits, network/login rotation and transitions involving either protected carrier preserve the learned SSH pin until explicit owner reset. Only a genuine Direct-to-Direct endpoint change automatically clears trust. Network identity never replaces SSH login or proof/TOFU. The minimal App reader is delivered separately in [#37811 / PR #37814](https://github.com/okou-ai/okou/pull/37814): it distinguishes bound/retained Tailscale, preserves explicit reset/delete and does not open the legacy carrier editor. That source is not proof of a serving App. The backend contains no Platform reader changes after this split; full setup/recovery remains #37640's delivery.

## Current Runner authority

`POST /api/runners/runs/:runId/ssh/resolve` admits a protected `resolved_tailscale` snapshot after current exact Run, winning Runner identity, owner/Agent visibility, saved host, chat permission, independent login and configuration visibility checks. Like Direct/Cloudflare, it completes that **initially admitted snapshot** across external decrypts without holding DB locks or adding a Tailscale-only final-KMS recheck. A concurrent rotation/revocation can therefore occur before the old snapshot handoff completes. Subsequent fresh resolution checks current authority; pin/observation checks current host generation and permissions. This is the selected common policy, not a bounded revocation promise.

Generated secret DTOs remain bounded, Deserialize-only and non-Debug/non-clone/non-serializable. OAuth material stays trusted-side and never enters guests, CLI arguments, snapshots, artifacts or diagnostics. The qualified native sibling derives a fresh bounded registration key at fixed official endpoints; it never passes OAuth credentials into the SDK.

Tailscale uses [Run-lifetime SSH authority](runner-ssh-authority.md): resolve on first use/cache miss, cache within the exact Run, and evict/cancel on delivered host/Run invalidation or Run/sandbox teardown. There is no periodic authorization renewal, lease endpoint or fixed authorization TTL. Missed notices may retain old access/configuration/credentials until Run end, including after rotation or revocation. API/notification outages alone do not revoke admitted caches; reconnect must not revive invalidated authority. Historical observations are evidence, not grants. Native carrier ownership/cancellation/cleanup remain separate qualification gates.

## Deployment and acceptance

**Separate reader and producer releases are required.** Release the response/reader-only [PR #37814](https://github.com/okou-ai/okou/pull/37814) first and verify its App is actually serving in an earlier completed release under [#37812](https://github.com/okou-ai/okou/issues/37812). Every release still promotes API before App. Merging separate PRs, creating a tag/version or building an artifact in the same unreleased aggregate does not establish the reader floor. Only the later backend producer release may require that already-live sufficient reader version, retaining an already-higher valid floor. No numeric target is selected by this split; #37651 remains Draft until the readiness evidence and selected floor are complete. Missing/malformed versions and non-App callers remain intentional general-floor exceptions, not authorization or a writer/fleet barrier.

Before merge eligibility, recheck that the unshipped foundation migration follows the current immutable main frontier. Rebasing generated feature metadata does not establish serving-App readiness or authorize a production writer cutover; immutable main migrations remain unchanged.

Generated migration `1357_tailscale_private_ssh` adds configuration/binding and required `transport: direct | cloudflare_access | tailscale`, without a carrier default or a `rebind_transport` column. Direct requires both configuration IDs null; a protected carrier permits only its corresponding ID. A missing corresponding ID means rebind, never Direct. Canonical readers derive `needsRebind` from these fields; the optional Direct representation, protected response objects and public `configId` stay unchanged. Existing credentials, pins, permissions and observations retain their shape and meaning.

The expand phase backfills historical bound/retained Cloudflare and Direct rows before enforcing NOT NULL. The physical `needs_rebind` column is temporarily retained as a compatibility shadow (`legacyNeedsRebind` in the schema) for outgoing Cloudflare readers. New writers mirror it atomically with canonical carrier/reference changes; a check rejects disagreement. Canonical readers never use it as authority. There are no DB triggers, hidden generation changes or fallback carrier defaults.

**Coordinated API writer cutover is required before applying this migration.** Quiesce/drain outgoing SSH and protected-configuration mutation handlers, including in-flight writes and reachable rollback writers; apply the migration; promote/verify the explicit-transport API writer floor before resuming writes. New-column readers require the migration first. Do not apply this as an uncoordinated rolling schema update: outgoing inserts omit the required carrier and old carrier transitions cannot satisfy canonical constraints. Real migration tests prove these unsupported writes fail closed, not continued old-writer compatibility. This PR performs no deployment or production quiescence. Once serving/rollback readers no longer consume the shadow, a separate contract migration can remove its check and physical column. This internal-model change alone requires no forced frontend upgrade because API responses are unchanged; it does not waive the independent Tailscale reader floor below.

Before **any Tailscale-capable writer**, coordinate serving/rollback API and App/cached readers that understand both linked and `needsRebind` Tailscale hosts. An older API can infer Direct or mislabel retained private hosts as Cloudflare. UI-off is not a writer/fleet/rollback barrier. Once private state exists, do not roll back below the reader floor or convert/delete rows as rollback cleanup. This PR does not deploy or establish an operational floor.

The planned default-off `TailscaleAccess` switch belongs only to #37640's UI. API/Runner never evaluate it; configurations have no enabled state. Hiding UI does not revoke permissions, stop sessions or reset pins. A qualified compatible official Rust fleet precedes usable private JIT. SDK lifecycle/routing/privacy, locked musl builds, real-provider/end-to-end/performance acceptance, deployment, activation and parent closure remain separate gates. Local teardown cannot prove a remote command stopped or undo partial transfer; retain unknown effects/no replay. The selected SDK has no supported logout API, and eventual ephemeral auto-removal is not a hard deadline.
