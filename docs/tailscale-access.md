# Tailscale private SSH access

Delivery parent: [#36137](https://github.com/okou-ai/okou/issues/36137). The API/data foundation is [#37638](https://github.com/okou-ai/okou/issues/37638); the qualified official native Rust carrier and setup/recovery UI are separate siblings [#37639](https://github.com/okou-ai/okou/issues/37639) and [#37640](https://github.com/okou-ai/okou/issues/37640). This foundation does not make private SSH operational. The current Runner explicitly rejects the new JIT variant before DNS, OS TCP or SSH; it never treats it as Direct/Cloudflare. No provider request or tailnet join occurs when saving a configuration or host.

## Reusable configuration

Canonical API routes are `/api/tailscale/configs` (list/create) and `/api/tailscale/configs/:configId` (detail/update/delete). Personal configurations are visible/manageable only to their owner in the selected organization. Organization members may select shared metadata; only Organization admins may create/update/delete shared configurations. Scope is immutable in v1. There is no conversion or force-detach operation. All delete paths reject an in-use configuration, including another member's references, without disclosing their host IDs/names.

Create requires an explicit UUID, name, nonempty bounded unique registration tags (1–16 `tag:` names), and OAuth client ID/secret (write-only, individually bounded to 4096 ASCII non-whitespace characters). A retry with the same UUID/owner reconciles with 204 without overwriting credentials or metadata; a foreign resource ID conflicts. Updates use `expectedRevision`. A rename advances revision only; explicit credential replacement or effective tag/enabled changes also advance configuration generation. That generation is independent of host generations: rotating one shared configuration does not update/lock every saved host. Configuration change sends metadata-only `tailscale:changed`; effective changes additionally send post-commit exact-owner/host invalidations. Realtime is best-effort eviction, not a grant or the lifetime cutoff.

Metadata returns scope, name, tags, enabled, revision/generation, timestamps and only the caller's referencing SSH host IDs/names. It never returns credentials or ciphertext. Credentials use the established stored-secret envelope; KMS encryption/decryption is outside short database transactions. Saving does not verify an OAuth client, create an auth key/node, grant chat access or imply SSH readiness.

## Saved SSH hosts

`transport: { type: "tailscale", configId }` selects permitted existing configuration. `transport: { type: "tailscale", create: { id, name, credentials, tags } }` atomically creates a Personal network, independently of a selected/new SSH login. A failed binding, ID collision or stale host editor leaves no new login/network rows. Host updates serialize/recheck the expected host generation after external preparation. Scoped restrictive foreign keys and the mutually exclusive transport/rebind constraint protect bindings.

SSH login rotation prepares encryption outside its transaction, then locks current referencing hosts before the credential. Hosts use `FOR NO KEY UPDATE`: it serializes host mutations while remaining compatible with the RESTRICT deletion check's key-share lock, avoiding a credential-to-host wait cycle. The exclusive credential lock fences new foreign-key bindings; if a host joined while acquiring that lock, the update releases its unwritten transaction and scans once more in a new transaction rather than taking another host lock in reverse order. Another binding-set change conflicts before writing. This bounded pre-write rescan does not repeat KMS preparation, a successful or ambiguous mutation, or a provider action. Effective login changes advance all protected current host generations, including first bindings created during preparation, while a credential-name-only edit preserves them. Returned references and post-commit invalidation use that current binding set, not a pre-KMS snapshot. Credential deletion takes the credential fence and checks current references without host locks before issuing DELETE; referenced deletion never enters the FK's reverse-order host lock path. Restrictive FK checks remain a final integrity guard.

Ports are 1–65535, not Cloudflare's 443-only rule. Syntax-only saved targets support Tailscale assigned IPv4/IPv6 literals, selected-tailnet short names and exact FQDNs. No URL, wildcard, zone, Unicode label, alternate IP spelling or arbitrary private/public literal is accepted. The native sibling must qualify short names using the current self-node tailnet suffix, match the canonical name and assigned address of the exact eligible peer, exclude self/foreign/shared-tailnet peers and advertised routes, and never use public/system DNS or fallback carriers. Saved-name matching is not general MagicDNS/split DNS.

Omitted transport preserves the saved binding, including disabled networks. Retained configuration/credential/trust metadata never becomes Direct. Configuration disable, outage, replacement or rebinding preserves the SSH pin; actual destination changes and explicit owner reset retain existing trust rules. The current App can display/remove/reset retained Tailscale hosts but deliberately cannot open its legacy carrier editor for them; full forms/recovery belong to #37640. Network identity never replaces SSH username/key/password or host-key verification.

## Current Runner authority

`POST /api/runners/runs/:runId/ssh/resolve` delivers a protected `resolved_tailscale` response only after exact current Run, winning Runner UUID/heartbeat generation, Run owner/Agent visibility, saved host/current per-chat permission and visible enabled configuration checks. It supplies independent SSH authentication and write-only OAuth material/tags plus the network ID/generation. Authority is rechecked after KMS for this variant. Generated Rust DTOs remain bounded, Deserialize-only and non-Debug/non-clone/non-serializable for all secret-containing types. Never send them to guests, CLI arguments, snapshots, artifacts or diagnostics. No Tailscale OAuth material is passed into the SDK: the trusted native sibling derives a fresh bounded registration key at the fixed official endpoints.

`POST /api/runners/runs/:runId/ssh/lease` takes only connection ID, winning Runner identity, expected host generation and required `expectedTailscaleConfig: { configId, generation }`. The response is `unavailable` or `permitted` with `validForMs: 60000`; there is no credential/KMS/provider IO. The native owner must acquire before key/node creation, anchor its monotonic deadline before the request, renew every 30 seconds while startup/stream/Session/SFTP owns the host, and stop local use on loss/expiry. Delayed responses cannot extend the deadline. This foundation does not implement native timers, node ownership or cleanup qualification.

Runner pin and observation requests retain their legacy Direct/Cloudflare shape. For Tailscale, the exact configuration tuple is required in addition to host generation. Stale/missing tuples cannot pin and their observations are ignored. Owner observations are filtered through the current visible enabled configuration tuple, so a rotation/disable cannot display stale successful evidence. Historical snapshots have no cascading configuration FK and never grant access.

## Deployment and acceptance

Migration `1319_tailscale_private_ssh` is generated additive Drizzle schema. Apply it before deploying new-column readers. Existing Direct/Cloudflare rows, SSH credentials/pins and permissions are unchanged. Before deploying **any Tailscale-capable API writer**, coordinate compatible serving and rollback API readers and App/cached-client readers that understand retained Tailscale bindings. Outgoing readers can otherwise infer Direct or mislabel Cloudflare. UI-off is not a data-write/fleet barrier; authorized API callers can still write. Do not roll back below that reader floor once any binding exists, delete/convert rows as rollback cleanup or add a backend rollout flag to substitute for deployment coordination.

The planned `TailscaleAccess` switch belongs only to the setup sibling's UI and defaults off. API/Runner authority never evaluates it. Hiding UI does not revoke permissions, disable configuration, stop sessions or reset pins. Revocation is configuration disable or actual host/chat permission removal with invalidation and finite native lease enforcement.

Usable private JIT requires the qualified compatible official Rust Runner fleet first. SDK public ownership/cancellation, exact routing, physical socket/task teardown, privacy and both locked musl builds remain mandatory sibling qualification gates. Real-tailnet acceptance, performance/capacity evidence, deployment, feature overrides/activation and parent closure are not authorized by a merged foundation PR. Local teardown cannot prove a remote command stopped or undo partial transfer; preserve unknown effects/no automatic replay. The selected SDK has no supported logout API; eventual ephemeral auto-removal is not a hard cleanup deadline.
