# Direct WSS: local host/Runner endpoint readiness (#37024)

This is **not** an enabled public WSS service. It establishes one short-lived, host-attested _local_ Unix-listener record per `runner_id` for #36981. The existing `runner_state` heartbeat, scheduler, PAT/fleet token and diagnostic `runner_hostname` are unchanged and cannot publish a Web endpoint. There is no WSS generation key or check.

## Trust and installation boundary

The API environment `OKOU_WSS_HOST_PROOFS` is optional and absent by default. It contains a JSON list of unique objects shaped like `{"id":"<uuid>","hostname":"runner-1.example.test","credentialSha256":"<64-lowercase-hex>"}`. Operators, not a public API, bind each host ID to its canonical DNS name and **SHA-256 digest** of a separate cryptographically random `okou_wss_host_`-prefixed token (32 random bytes encoded in base64url). Reject duplicate IDs, hostnames or digests. The raw token is never checked into the repository or put in Runner configuration; #37028 provisions it through a root-only host secret and installs a singleton host-side registrar. Rotate the API-pinned digest and host secret in a coordinated cutover; this first contract allows one credential per host, so readiness may briefly expire during rotation. Do not assume an overlap window or publish a ticket during the cutover. Do not use the existing official Runner fleet secret, a PAT, or the Computer Use host token.

The host registrar in `ansible/scripts/wss_host_registrar.py` is **not** installed by this PR. When later installed, it runs on the host, verifies that `/run/okou-ws/<runner_id>.sock` is a real socket with the expected Runner UID, connects with a deadline, and asks the listener for `GET /internal/wss-ready/<runner_id>?nonce=<32 lowercase hex>`. It requires `HTTP/1.1 200` and exactly `{"runnerId":"<runner_id>","nonce":"<same nonce>"}` before each API `PUT`. #37027 must implement this private listener response; Caddy only proxies `/ws/<runner_id>`, never the readiness path. #37028 must provision the directory and socket permissions so untrusted users cannot create/substitute a listener. A live-path connect is not sufficient without the identity response. The API trusts the **host-bound registrar's** fresh assertion; it cannot itself inspect a remote Unix socket. A compromised host credential or host is an incident at this trust root.

The API's `PUT /api/runners/wss-readiness/:runnerId` accepts only that separate host bearer token and a local proof containing a random nonce and observed time no older than 10 seconds. The server assigns the host from the pinned credential, not the request or heartbeat, and leases readiness for 15 seconds. The host reprobes every 5 seconds and sends `DELETE` on a failed probe or shutdown. Lack of renewal expires readiness even if shutdown is missed. `GET` is host-authenticated and reports only whether that host's _local_ endpoint is ready; `publicIngressReady` is **always false** in this PR. Records never transfer between hosts just because a lease expired. A conflicting host claim atomically quarantines the `runner_id` for **both** hosts; even its original host cannot renew or resolve it until an operator reviews the collision and explicitly decommissions/rebinds the record. A true host migration likewise requires an explicit reviewed decommission/rebind, not an API self-claim. A same-host sequential restart can renew only after a fresh probe of the new socket.

## Publication gate and rollback

No API ticket route is added here. `resolveLocalWssEndpoint()` also returns `publicIngressReady: false`; it does **not** prove browser-trusted TLS, DNS, Caddy routing, firewall reachability or run ownership. #37025 must reject ticket issuance until independent public-ingress proof (#37028/#37030) and the other parent gates are verified. If configuration is missing/malformed, a listener disappears, a host is removed, storage fails, or a lease expires, reads fail closed. Disable/rollback by withdrawing the host credential and stopping the registrar; existing canonical chat delivery remains unchanged. Production DNS/firewall/deployment/activation need separate authorization.

## Local verification

- `python3 -m unittest ansible/scripts/test_wss_host_registrar.py` checks the private probe contract with a fake Unix listener (not a real WSS handshake).
- Focused API contract/route tests check host authentication, lease and foreign-host collision; the DB migration follows `turbo/packages/db/MIGRATIONS.md`.
- Full browser→Caddy→Runner→Guest testing, TLS certificate renewal and mixed-version drain/restart belong to #37030, not this local-readiness prerequisite.
