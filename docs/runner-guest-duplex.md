# Private run-scoped Guest duplex (#37026)

This is **not a public endpoint or a product message protocol**. #37027 owns ticket redemption, first-frame WSS admission, required listener startup/health and downstream forwarding. #37030 owns real browser/Caddy/Guest acceptance. This slice neither enables ticket issuance nor authorizes production ingress.

## Attachment contract for #37027

The owning Runner creates one `runner_remote::guest_duplex::RunGuestChannels` instance in `ExecutorConfig`. The executor registers the exact `ExecutionContext.run_id` only while it holds that run's prepared sandbox; it drops the registration before sandbox cleanup, park and reuse. #37027 must share **that same instance** with its listener. After redeeming a ticket, call `open(exact_run_id)` and require success **before** sending `auth.ok`. Never create a second registry, consult status.json/DB, infer a sandbox from the socket path or accept a client-supplied sandbox ID. A missing run, unsupported/old guest, full run, cancelled run, mismatched provider sandbox ID or prior execution epoch returns an error. The listener must close its WSS stream on `Channel::cancelled()` or retain `Channel::cancellation()` before splitting and select `ChannelCancellation::cancelled()` independently of both IO halves; drop the halves when it fires; run completion/revocation must not keep an operation reservation alive. An error from `send`, `recv` or `finish_send` closes that WSS stream, never resumes parsing a partial frame. #37027 independently remains fatal on WSS bind/accept-loop failure; Guest transport errors fail individual attachments closed.

`Channel::split()` gives independent Sender/Receiver ownership for forwarding in two directions; the caller keeps the cancellation observer separately. Each send carries one opaque binary frame of at most 64 KiB; no JSON, routing, chat receipts, SSH/VNC or exec content is interpreted. Send/recv ordering is per direction within one stream; unrelated streams have no cross-stream ordering. `Sender::finish()` half-closes host→Guest while receiving can continue. Guest EOF yields `None`; malformed/oversized/partial frames return errors and poison only that stream. Dropping both halves releases the per-run permit and the provider's normal-operation reservation. A run permits at most eight concurrent streams. No unbounded task or application queue is created: synchronous framed writes respect Unix/vsock backpressure, a frame is limited to 64 KiB, the Guest holds at most eight workers plus one pending connection, and each private accept, Guest-control lookup and activation stage has a two-second timeout. #37027 must impose its own overall admission deadline.

## Provider and Guest compatibility

Firecracker binds one private 0600 vsock listener for port 52002 under its validated per-sandbox 0700 runtime directory, independently of control port 1000 and Guest RPC port 52001. Only the Guest initiates a connection; the host accepts it against the exact current `ParkCoordinator` run binding and activates it with one byte after acquiring the normal-operation reservation. Park/termination cancels the assignment and its streams; the endpoint is dropped/rebound across park/unpark, never looked up from a reused sandbox cache. Guest control server launches an independent worker in the deployed guest; it maintains one pending connection, accepts activation, and provides an inert echo fixture with length-prefixed frames. No business consumer is wired here. An older guest image without this worker times out closed; a newer guest running against an older Runner has no endpoint and its worker retries privately. Rebuild and validate the guest image in #37030's integrated path before any rollout gate is lifted. No `OKOU_WSS_TICKET_ISSUANCE_ENABLED` setting is assumed.
