## Declaration decisions

- **S1 — delete one parameterized declaration, two branches (`user`, `organization`):** `artifact-account-erasure.test.ts` — `erases multiple batches of projection-owned historical files through the verified Clerk %s entrypoint`. The complete case starts by inserting 501 ownerless legacy files and registry projections, observes them through DB readers, then invokes a real provider event. The final API 404 does not make the setup public. The existing `erases independently retained files by %s ownership after Run deletion` matrix in `artifact-catalog.bdd.test.ts` independently constructs uploads and the provider event and observes outsider preservation; its owned post-deletion readback limitation is recorded below.
- **S2 — delete one declaration:** `agents-by-id.test.ts` — `removes abandoned publication fences on ordinary deletion`. Its only assertion is a private token count after privately seeding a reservation. The adjacent `deletes the caller's own agent`, foreign-org/non-owner rejection, owner API-key deletion and instruction-volume cleanup cases remain.
- **S3 — delete one declaration:** `agents-by-id.test.ts` — `removes the user's publication fences on verified Clerk user deletion`. Both decisive setup and observations use private publication rows. The production user cleanup removes user-owned lifecycle data but does not delete Agents in a surviving organization (`deleteClerkUserLifecycleData$`, `deleteUserData$`, and `agentDetail`). Thus Agent read-404 is not a valid substitute. The original case has no independent public assertion to retain; remove it without changing production semantics or adding a filler test.
- **S4 — delete one declaration:** `shared-threads.test.ts` — `rolls back the share when the real artifact write fails after title degradation`. A DB trigger forces artifact INSERT failure after title-provider 429; the trigger is the decisive construction. Existing `creates one private-content-safe snapshot with $name` retains all five title-provider outcomes, including normal 429/401 handling, and public privacy, auth, ownership, selection, cancellation and client-ID cases remain.

Totals: four whole declarations removed; one of those is parameterized and contains two rows. Zero declarations are rewritten. Zero branches are removed from retained parameterized declarations; no new declaration or filler case is added.

## Actual construction and observation chains

- `artifact-catalog.bdd.test.ts`: `catalogActor` uses normal Stripe/onboarding and personal-subscription APIs; `uploadFile` creates a chat Run, heartbeats and claims it through the actual Runner protocol, and uploads through its returned credential. Normal Agent deletion retains the file; the provider Clerk deletion event is then delivered and the unrelated owner still reads their file URL/catalog. The retained owned 404 assertions mock the now-deleted actor/session (and, in one branch, organization), so this review does not certify those readbacks as reachable by a surviving caller or the entire retained matrix as compliant. This pre-existing limitation is outside the ten retired definitions and earns no completion credit. No part of this matrix proves the removed historical physical-row invariant.
- S3: `createAgent` prepares external S3 mocks and calls the real agents route. `createWebhookCallbackApi.requestClerkWebhook` calls the registered production webhook, with the verified event supplied at the external Clerk SDK boundary. Those steps are public, but the case fabricates all pending reservations and checks only raw generation/token counts. `deleteClerkUserLifecycleData$` and `deleteUserData$` leave Agents in a surviving organization, and `agentDetail` still exposes those public Agents; deleting the user is not proof of Agent deletion. The private fence guarantee has no independently useful public replacement in this case.
- S4's retained shared-title matrix uses `prepareShare`: normal paid entitlement webhook, public personal-subscription connection/model selection, Agent creation and user chat events. It observes the public shared snapshot/meta and authenticated artifact catalog. Removing the trigger case does not change these helper implementations or provider branches.
